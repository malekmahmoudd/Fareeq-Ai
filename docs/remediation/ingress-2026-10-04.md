# B2 — bounded ingress before parsing

Root cause verified: FastAPI resolves UploadFile/Form bodies through Starlette's multipart parser before entering documents.upload or voice.transcribe. Endpoint Content-Length/file-read checks cannot bound earlier parser resource use. The previous Caddyfile imposed no body limit/deadline.

A pure ASGI middleware now checks declared length, counts actual streamed bytes (including chunked bodies), counts multipart parts incrementally, caps per-part headers, and applies total/idle body budgets before invoking FastAPI. Invalid, incomplete or disconnected input never enters the app parser. A bounded number of bodies may be collected per worker. Valid bodies are replayed unchanged; later receive calls reach real disconnect events so streaming cancellation still works. Existing endpoint file-size/type/ownership checks remain.

Defaults: generic body 1 MiB; documents 10 MiB plus 64 KiB multipart envelope; voice 4 MiB plus 64 KiB; eight multipart parts; 8 KiB headers per part; 60 seconds total, 10 seconds idle, eight concurrent body collections. Settings and backend/.env.example expose these bounds. Buffering adds at most one bounded-body latency before app processing; this app has no request-streaming endpoint. Raising upload limits requires coordinating the proxy's edge limit and capacity budget.

Caddy now caps all bodies at 11 MB (MAX_REQUEST_BODY can override), caps header reads at 10 seconds and body reads at 60 seconds. Full-duplex HTTP/1 handling prevents Go's request draining from delaying an early response. No response write deadline was added to the SSE path. Config validated against the production-pinned Caddy image.

Twelve new ASGI/application tests cover declared oversize without reads, anonymous pre-parser rejection, actual chunked size, part count across one-byte chunks, valid byte-for-byte multipart replay, malformed/duplicate lengths, idle/total timeout, disconnect, incomplete body and capacity rejection. The host suite passed 553 with four infrastructure skips; the production image passed all 557.

Fresh HTTPS probes against production-pinned Caddy/PostgreSQL/backend: declared oversize with no body -> 413; chunked nine-part form -> 413; chunked oversized JSON -> 413; stalled body -> 408. See evidence/release-https-ingress.json. The original delayed-response probe exposed the proxy draining issue; it passed only after adding full-duplex/deadlines.
